# Анонс Rspress 2.1.0

![Баннер Rspress 2.1](/rspress-v2-1-banner.png)

Rspress 2.1.0 уже доступен. Этот выпуск включает:

- **SSG-MD включён по умолчанию**: генерация `llms.txt` и Markdown-версий страниц без дополнительной настройки.
- **Новые WebMCP-инструменты**: браузерные Агенты могут напрямую запрашивать, читать и перемещаться по документации.
- **Обновлённые стили панели поиска**: улучшены десктопные и мобильные раскладки, результаты поиска и пустые состояния.
- **Встроенная карта сайта, чистые URL и проверка якорей включены по умолчанию**.
- **Переход на режим данных React Router** с восстановлением прокрутки и новым экраном ошибки загрузки страницы.

## SSG-MD включён по умолчанию

[SSG-MD](/guide/basic/ssg-md) рендерит MDX и React-компоненты в Markdown, чтобы Агенты могли их читать.

Сайт Rspress получил **100/100** в [оценке AFDocs](https://x.com/Soon_Iter/status/2090359544769913185). Начиная с Rspress 2.1.0, SSG-MD включён по умолчанию, поэтому больше не нужно явно задавать `llms: true`.

Продакшен-сборки генерируют эти файлы вместе со страницами HTML:

```text
doc_build/
├── llms.txt           # Индекс документации для выборочного чтения
├── llms-full.txt      # Полное содержимое документации
└── guide/
    ├── getting-started.html
    └── getting-started.md
```

В статье [Как создать сайт, удобный для агентов](/blog/agent-friendly-website) мы объясняем, как объединить SSG-MD, llms.txt и согласование содержимого Markdown, чтобы помочь Агентам обнаруживать и читать документацию.

## Встроенные WebMCP-инструменты

[WebMCP](/guide/basic/webmcp) позволяет сайтам предоставлять инструменты браузерным Агентам. Rspress 2.1.0 включает эти шесть инструментов документации по умолчанию:

| Инструмент            | Назначение                                                                                                                                      |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `get_site_info`       | Получение информации о сайте, языках, версиях, навигации и текущей боковой панели                                                               |
| `list_pages`          | Фильтрация страниц по языку, версии и ключевым словам                                                                                           |
| `get_page`            | Чтение метаданных, структуры и [SSG-MD-документации](/guide/basic/ssg-md) конкретной страницы без перехода (включается вместе с SSG-MD)         |
| `get_current_page`    | Чтение метаданных, структуры и [SSG-MD-документации](/guide/basic/ssg-md) текущей страницы (включается вместе с SSG-MD)                         |
| `search_docs`         | Поиск по локальному индексу документации для текущего языка и версии                                                                            |
| `navigate`            | Переход на внутреннюю страницу и возврат информации о странице после её загрузки                                                                |

Новый хук [`useWebMcp`](/ui/hooks/use-web-mcp) также позволяет компонентам регистрировать собственные инструменты:

```tsx
import { usePage, useWebMcp } from '@rspress/core/runtime';

export function PageTitleTool() {
  const { page } = usePage();

  useWebMcp({
    name: 'my_site_page_title',
    description: 'Get the current page title',
    annotations: { readOnlyHint: true },
    execute: () => ({ title: page.title }),
  });

  return null;
}
```

Инструменты регистрируются при монтировании компонента и удаляются при его размонтировании. Инструменты для всего сайта регистрируйте в layout-компонентах, а инструменты для отдельных страниц — на соответствующих страницах.

WebMCP по-прежнему является экспериментальным API браузера. Для него требуется включённый `document.modelContext` и доступ по HTTPS или с localhost. Другие браузеры по-прежнему могут читать сайт как обычно.

Установите `webMcp: false`, чтобы отключить встроенные инструменты. Это не влияет на собственные инструменты, зарегистрированные через `useWebMcp`.

## Обновление стилей панели поиска

Стили локальной панели поиска в стандартной теме обновлены:

- Более широкая панель на десктопе, без рамки поля ввода и теней у отдельных результатов.
- Боковые отступы на мобильных устройствах, скорректированные размеры поля ввода и кнопки отмены, а также прокрутка результатов внутри панели.
- Перенос длинного текста и выровненные отступы в пустом состоянии.

![Обновлённая панель поиска](https://assets.rspack.rs/rspress/assets/rspress-full-text-search.png)

Подробнее см. в разделе [Полнотекстовый поиск](/guide/start/introduction#full-text-search) и в [PR #3683](https://github.com/web-infra-dev/rspress/pull/3683).

## Встроенная карта сайта

Rspress 2.1.0 генерирует `sitemap.xml` по умолчанию при продакшен-сборке. Устанавливать `@rspress/plugin-sitemap` больше не нужно.

Задайте адрес развёртывания через `siteOrigin` и подкаталог через `base`, чтобы генерировать абсолютные URL:

```ts title="rspress.config.ts"
import { defineConfig } from '@rspress/core';

export default defineConfig({
  siteOrigin: 'https://example.com',
  base: '/docs/',
});
```

Используйте опцию верхнего уровня [`sitemap`](/api/config/config-basic#sitemap), чтобы настроить приоритеты, частоту обновления и отдельные записи страниц. Существующие проекты могут использовать её вместо `@rspress/plugin-sitemap`.

Карта сайта генерируется даже при `ssg: false`. Установите `sitemap: false`, если карту генерирует другой процесс.

## Чистые URL по умолчанию

[`route.cleanUrls`](/api/config/config-basic#routecleanurls) теперь по умолчанию имеет значение `true` вместо `false`. Сгенерированные ссылки на обычные страницы не содержат `.html`, например `/guide/getting-started.html` превращается в `/guide/getting-started`.

Ваша платформа для развёртывания должна отдавать `/foo.html` напрямую, когда запрошен `/foo`. Установите `route.cleanUrls: false`, если хостинг не поддерживает такое поведение или вам нужно сохранить суффикс `.html`.

## Проверка внутренних якорей по умолчанию

[`markdown.link.checkAnchors`](/api/config/config-build#markdownlinkcheckanchors) теперь по умолчанию имеет значение `true` вместо `false`. Rspress проверяет существование связанных разделов, находя устаревшие ссылки вроде `/guide/config#old-heading` после переименования заголовка.

Проверка охватывает внутренние ссылки на текущую страницу, а также относительные и абсолютные ссылки на Markdown- и MDX-страницы, а внешние URL пропускает. Используйте `markdown.link.checkAnchors.excludes` для якорей, которые нельзя определить статически, например динамически создаваемых, или установите `checkAnchors: false`, чтобы отключить проверку.

## Режим данных React Router

Теперь Rspress использует режим данных React Router. Ссылки стандартной темы и вызовы `useNavigate()` загружают данные и код страницы назначения до смены URL и содержимого страницы. Во время загрузки текущая страница остаётся видимой.

В React Router 7 функции навигации, возвращаемые `useNavigate()` и `useLinkNavigate()`, поддерживают `await`, чтобы дождаться завершения перехода.

Новая страница ошибок `ErrorLayout` предлагает действия перезагрузки и возвращения на главную, если не удалось загрузить или отрендерить страницу. В режиме разработки она также показывает детали ошибки. Кастомные темы могут заменить `ErrorLayout`.

## Восстановление прокрутки

Rspress восстанавливает позицию прокрутки, когда читатель возвращается назад, переходит вперёд или перезагружает страницу. Например, прочитав часть длинной страницы, перейдя на другую и вернувшись назад, читатель может продолжить с того же места. React Router также обрабатывает навигацию по якорям.

## Чек-лист обновления

- [ ] Обновите `@rspress/core` и любые используемые в вашем проекте официальные плагины, например:

  ```json title="package.json"
  {
    "devDependencies": {
      "@rspress/core": "~2.1.0",
      "@rspress/plugin-preview": "~2.1.0",
      "@rspress/plugin-twoslash": "~2.1.0"
    }
  }
  ```

- [ ] Проверьте совместимость SSG-MD с серверным рендерингом. Оберните зависимый от браузера контент в [`BrowserOnly`](/ui/runtime-components/browser-only). Установка `ssg: false` не отключает SSG-MD. Сайтам, которые не могут поддерживать серверный рендеринг, нужны и `ssg: false`, и `llms: false`.
- [ ] Если вы кастомизировали стили темы `SearchPanel`, после обновления визуально проверьте десктопную и мобильную раскладки, чтобы убедиться, что всё выглядит как ожидается.
- [ ] Проверьте конфигурацию карты сайта. Замените `@rspress/plugin-sitemap` на встроенную опцию `sitemap` или установите `sitemap: false`, если карту генерирует другой процесс.
- [ ] Проверьте, что ваш хостинг поддерживает URL без `.html`, например отдаёт `/foo.html` напрямую, когда запрошен `/foo`. Установите `route.cleanUrls: false`, чтобы сохранить прежний формат ссылок.
- [ ] Запустите продакшен-сборку и исправьте некорректные якоря. Исключите динамически создаваемые якоря с помощью `markdown.link.checkAnchors.excludes` или установите `checkAnchors: false`, чтобы отключить проверку.

Полный список изменений см. в [Release Notes v2.1.0](https://github.com/web-infra-dev/rspress/releases/tag/v2.1.0).
